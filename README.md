# バンド練習レビューサービス (MVP)

設計書 v0.2 に基づくPhase 1+2の実装(ローカル管理機能+共有機能)です。

## 含まれる機能

- 録音ファイルのアップロード → 無音検出による自動分割 → **手動での分割点の追加/削除・プレビュー再生(速度切替つき)** → タイトル編集 → 保存
- Session一覧・Session詳細・Track再生
- ★お気に入り、タイムラインコメント(クリックでその位置にジャンプ、**投稿者の表示名つき**)
- 共有リンクの発行(閲覧用 / 編集用)、共有相手はログイン不要で閲覧・コメント・お気に入り編集が可能
- 共有後は、あなたの端末での変更(タイトル・お気に入り・コメント・メモ)が**自動で共有リンクに反映**されます
- 新規録音の入口は「テープをデッキに挿入する」ワンショットアニメーション付き

## 音声解析について

無音検出・分割ロジックは、既存の`rehearsal-rec-splitter.html`(build: 2026-07-10)の実コードから移植しています。

- RMS計算は0.2秒刻み、閾値は**絶対dBFS基準**(デフォルト-30dB。グローバル最大振幅基準ではありません)
- 「無音判定時間」「無音判定閾値」「最小演奏時間」の3スライダーで調整でき、「この設定で再判定」ボタンで(音声の再デコードなしに)高速に再判定できます
- WAV書き出しロジックも既存コードと同じです
- 波形は「プレビュー」「分割点を編集」の2モード。
  - プレビューモードでは、全体/10分/5分/2分/1分のズーム切替ができ(元ツールと同じ幅)、タップした位置を中心に自動追従します。速度切替(1x/1.25x/1.5x/2x)つき
  - 分割点を編集モードでは、演奏区間内をタップして分割点を追加/削除できます(オレンジの縦線)。このモードは常に全体表示です
  - 再判定を行うと手動分割点・トリムはリセットされます
- 検出された各曲には個別のトリム編集(前後の開始/終了位置をドラッグで微調整、波形をタップした位置から範囲内プレビュー)、音量調整(-18dB〜+18dB)、**音質補正**、**EQ**がついています。隣の曲の範囲までは動かせないようになっています。これらはプレビュー再生にも、保存時のWAV書き出しにも反映されます(共有時のMP3にもそのまま引き継がれます)。**波形自体も音量調整に合わせて表示が変わり、音が割れる(クリップする)部分は波形が警告色になります**

## 音質補正・EQについて

曲ごとに、プリセットから選ぶだけで音を整えられます。

**音質補正(ダイナミクス)**

| プリセット | 内容 |
| --- | --- |
| なし | 録音そのまま |
| 軽く整える | 音量差をゆるやかにならす |
| しっかり整える | 小さい音も聴こえるまで持ち上げる |

**EQ(音色)**

| プリセット | 内容 |
| --- | --- |
| なし | 補正しない |
| ハイを上げる | 3.2kHz以上を+4dB(シャリっとさせる) |
| ローを上げる | 220Hz以下を+4dB(厚みを足す) |

内部の処理は `Source → EQ → コンプレッサー → メイクアップゲイン → 手動音量調整 → リミッター → ソフトクリッパー → 出力` の順です。リミッターとソフトクリッパーが最終段にあるため、「しっかり整える」を選んだうえで音量を上げても音が割れにくくなっています(補正が「なし」のときは従来どおり、上げすぎると割れます)。

プリセットの値を変えたい場合は `src/audio/audioAnalysis.js` の `ENHANCEMENT_PRESETS` / `EQ_PRESETS` を編集してください。プレビュー再生・WAV書き出し・共有MP3のすべてがこの定義を参照しているので、1箇所直せば全部に反映されます。

## 表示名(コメントの投稿者表示)について

- ログイン不要のため、「表示名」はブラウザ(端末)ごとにIndexedDBへローカル保存しています。別の端末で開くと別の表示名になります(同じ人でも端末が変われば再入力が必要です)
- 共有リンクを開いた相手も、その相手自身の端末で表示名を設定できます

## 共有後の同期について

一度共有したあと、あなたの端末でタイトル・お気に入り・コメント・メモを変更すると、**自動で共有リンク側にも反映されます**。競合したときは「後から変更した方が残る」(後勝ち)ルールです。変更した項目だけを送るので、共有相手が追加したコメントなどが消えることはありません。

ただし、**曲の分割や音質補正をやり直して音声そのものを差し替える**場合は、Session詳細の「共有リンクを表示」→「音声ごと再アップロード」が必要です。こちらは音声を含めて丸ごと上書きするため、共有相手が追加した内容が消える場合があります。

## 含まれていない機能(今後の課題)

- **複数Band対応**: 1ブラウザ=1Bandに簡略化しています。

## セットアップ手順

**2026年に入り、Cloudflareは新規プロジェクトの標準を「Pages」から「Workers with static assets」に切り替えています。**「Pages」を選んで作業を進めても、ダッシュボードのウィザードがWorkerのデプロイ画面(Deploy commandが`npx wrangler deploy`になっている画面)になることがあります。このプロジェクトは最初からその構成(`wrangler.toml` + `worker/index.js`)で作ってあるので、そのまま進めて問題ありません。

### 1. GitHubリポジトリを作る

このフォルダ一式(zipを解凍したもの)を、新しいGitHubリポジトリにアップロードしてください。GitHubの「Add file > Upload files」画面はフォルダをドラッグ&ドロップすると構造を保ったままアップロードできます。

`node_modules` と `dist` フォルダはアップロード不要です(Cloudflare側で自動生成されます)。`.gitignore` を同梱していますが、Web UIからアップロードする場合は単純にこの2つのフォルダを含めないようにしてください。

### 2. Cloudflareのアカウント・R2バケットを準備

1. Cloudflareダッシュボードにログイン(アカウントがなければ作成)
2. 左メニューの **R2 Object Storage** から新しいバケットを作成
   - バケット名は `wrangler.toml` 内の `bucket_name`(現在 `band-practice-review`)と**必ず一致**させてください。別の名前にした場合は、`wrangler.toml`の該当箇所を書き換えてからアップロードしてください。

### 3. Workersプロジェクトを作成(Git連携)

1. **Workers & Pages > Create application > Import a repository**(「Pages」を選んでも同じ画面に着地することがあります)
2. 先ほど作成したGitHubリポジトリを選択
3. ビルド設定の画面で、表示されている項目は基本そのままでOKです:
   - **Build command**: `npm run build`(そのまま)
   - **Deploy command**: `npx wrangler deploy`(そのまま。`wrangler.toml`を読んで、静的ファイルの配信・R2バインディング・APIの3つをまとめてデプロイしてくれます)
   - **Non-production branch deploy command**: `npx wrangler versions upload`(そのまま)
   - **Path**: `/`(そのまま。リポジトリ直下にプロジェクトがあるため)
   - **API token**: 自動生成のボタンがあればそれを使ってください(CIがデプロイするための権限用トークンです。手動作成の必要は基本ありません)
4. **Deploy**を実行(初回は数分かかります)

R2バケットのバインディングは`wrangler.toml`に書いてあるので、ダッシュボードで別途設定する必要はありません(バケットさえ事前に作成してあれば、デプロイ時に自動で紐付きます)。

### 4. 動作確認

発行されたURL(`https://xxxx.workers.dev`、または設定したカスタムドメイン)を開き、Android Chromeと Desktop Chromeの両方で以下を確認:

- 録音ファイルのアップロード→自動分割→保存
- Track再生・コメント追加・★変更
- 「共有」→発行された閲覧用リンクを別ブラウザ(シークレットウィンドウなど)で開いて内容が見えるか
- 編集用リンクでコメント追加・お気に入り変更ができるか

もし`/api/share`などが404になる場合は、R2バケット名が`wrangler.toml`の`bucket_name`と一致しているか、デプロイが最新のコミットで完了しているかを確認してください。
